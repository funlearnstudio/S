# GitHub syntax highlighting for SE

SE uses the `.se` extension and the TextMate scope `source.se`.

The official grammar lives in:

```text
vscode/syntaxes/se.tmLanguage.json
```

It is MIT-licensed with the SE repository and is designed to be usable by Visual Studio Code today and as the upstream grammar source for GitHub Linguist in the future.

## Current GitHub status

GitHub.com syntax highlighting and repository language detection are provided by **GitHub Linguist**. A repository cannot globally register a brand-new programming language only by adding `.gitattributes` or a local grammar file. The language itself must first be accepted by GitHub Linguist.

GitHub Linguist currently requires new language extensions to have substantial public usage before accepting them. Its contribution guide states that extensions expected to occur more than once per repository need at least **2,000 indexed files in the last year**, excluding forks, with reasonable distribution across different users and repositories.

Because SE is still a new language, the correct approach is:

1. Keep the official TextMate grammar maintained in this repository.
2. Use the VS Code extension for full local syntax highlighting now.
3. Grow public `.se` usage across real repositories.
4. Once the Linguist usage threshold is met, submit SE to `github-linguist/linguist` using this repository as the grammar source.

## Planned Linguist entry

When SE is eligible, the language definition should be based on the following entry, with `language_id` generated by Linguist's `script/update-ids` rather than chosen manually:

```yaml
SE:
  type: programming
  color: "#5B67F1"
  aliases:
  - se
  extensions:
  - ".se"
  interpreters:
  - se
  tm_scope: source.se
  ace_mode: text
```

The final color should be treated as a branding decision before the upstream submission; the value above is only the repository's proposed starting point.

## Upstream submission checklist

The eventual Linguist PR should include:

- the SE language entry in `lib/linguist/languages.yml`
- the official `source.se` TextMate grammar via `script/add-grammar`
- multiple representative, non-trivial `.se` samples
- tests required by Linguist
- a generated language ID
- GitHub code-search evidence showing enough `.se` usage in the wild
- the Linguist pull-request template filled in completely

## Repository-specific overrides

Do **not** map `*.se` to an unrelated existing language with a line such as:

```text
*.se linguist-language=Python
```

That would produce misleading language statistics and incorrect highlighting. Until SE is accepted upstream, VS Code provides the accurate highlighting experience while GitHub support remains pending Linguist eligibility.
